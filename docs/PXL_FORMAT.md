# Формат файла PXL (версия 3)

PXL — формат статичных изображений и анимаций для светодиодных матриц. Файл читается строго последовательно: кадр за кадром, команда за командой. Ориентирован на микроконтроллеры с маленьким буфером чтения (от 10 байт) и источниками данных без произвольного доступа (UART, SPI-flash, массив во flash, FatFS).

Описание соответствует `src/PXLFormat_v2.h` и `src/PXLParser.h`.

---

## 1. Общая структура

```
+----------------------+
| Заголовок файла      | 10 байт
+----------------------+
| Кадр 1               |
|   заголовок кадра    | 4 байта
|   команды            | переменная длина
+----------------------+
| Кадр 2               |
| ...                  |
+----------------------+
| Кадр img_frames      |
+----------------------+
```

- Длина кадра в байтах в файле не хранится. Конец кадра становится известен только после разбора всех его `frame_ops` команд. Поэтому перейти к произвольному кадру нельзя, вернуться назад — тоже, кроме как начать с первого кадра.
- Каждый кадр — **самостоятельное полное изображение**. Перед отрисовкой кадра буфер очищается в чёрный, поэтому кадр не может опираться на содержимое предыдущего.

## 2. Порядок байт

| Что | Порядок |
|---|---|
| Поля заголовка файла и заголовка кадра (`uint16_t`) | little-endian |
| Индекс пикселя внутри команд | **big-endian** |

Big-endian для индекса выбран намеренно: у сжатых форматов флаг типа команды — старший бит **первого** байта, и у команды с индексом этот бит совпадает со старшим битом индекса.

## 3. Заголовок файла (10 байт)

| Смещение | Размер | Поле | Описание |
|---|---|---|---|
| 0 | 3 | `type` | ASCII `PXL` |
| 3 | 1 | `version` | Версия формата: `3`. Версия `2` читается для совместимости, см. раздел 9 |
| 4 | 1 | `size_x` | Ширина изображения в пикселях, 1..255 |
| 5 | 1 | `size_y` | Высота изображения в пикселях, 1..255 |
| 6 | 1 | формат | Биты 0–3: `format_strip`; биты 4–7: `format_color` |
| 7 | 2 | `img_frames` | Число кадров, 1..65535. `1` — статичная картинка |
| 9 | 1 | `img_plays` | Число проигрываний: `0` — бесконечно, `N` (1..255) — проиграть N раз |

Проверки при открытии:
- `type` равен `PXL`, иначе `ERROR_INVALID_FILE`;
- `version` равен 3 или 2, иначе `ERROR_VERSION`;
- `size_x`/`size_y` совпадают с размером экрана, иначе `ERROR_SIZE`;
- `format_strip` равен 0, а `format_color` поддерживается, иначе `ERROR_FORMAT`;
- `img_frames` больше 0, иначе `ERROR_NOFRAMES`.

### 3.1. `format_strip` — раскладка ленты

| Значение | Имя | Статус |
|---|---|---|
| 0x0 | `STRIP_LINE` | Поддерживается. Индекс пикселя `index = x + size_x * y` |
| 0x2 | `STRIP_ZIGZAG` | Зарезервировано, не поддерживается |
| остальные | — | Зарезервировано |

### 3.2. `format_color` — формат команд

| Значение | Формат | Размер команды, байт | Индекс в команде |
|---|---|---|---|
| 0 | RGB, без сжатия | 5 | всегда |
| 1 | RGBA, без сжатия | 6 | всегда |
| 7 | RGB, разностное сжатие | 5 или 2 | только в несжатой команде |
| 8 | RGBA, разностное сжатие | 6 или 2 | только в несжатой команде |
| 14 | RGB555 + повтор/пропуск | 2 или 1 | никогда |
| остальные | — | — | зарезервировано (`ERROR_FORMAT`). Значение 2 (`COLOR_GRBA`) объявлено в enum, но не реализовано |

## 4. Заголовок кадра (4 байта)

| Смещение | Размер | Поле | Описание |
|---|---|---|---|
| 0 | 2 | `frame_timeout` | Время показа кадра, мс, 0..65535 |
| 2 | 2 | `frame_ops` | Число команд в кадре. Каждая команда — пиксель, повтор или пропуск — считается за одну |

**Команда** — один элемент потока кадра: пиксель, повтор или пропуск. Её длина (1–6 байт) зависит от формата и вида.

`frame_ops` — это число **команд**, а не пикселей: одна команда повтора закрашивает до 64 пикселей, а команда пропуска не закрашивает ни одного.

## 5. Модель декодирования кадра

Декодер хранит состояние, которое сбрасывается **в начале каждого кадра**:

| Состояние | Начальное значение | Смысл |
|---|---|---|
| `index` | `0xFFFF` («перед нулевым») | Последний затронутый пиксель. Команда без индекса делает `index + 1`, поэтому первая такая команда попадает в пиксель 0 |
| регистр цвета `color[4]` | `{0, 0, 0, 0}` | Последний реальный цвет (R, G, B, A) |

Каждая команда даёт **серию**: начальный `index`, длину `repeat` и цвет. После серии `index` указывает на её **последний** пиксель (`index += repeat - 1`).

| Вид команды | Что делает |
|---|---|
| Пиксель | Записывает цвет в регистр, `repeat = 1` |
| Повтор | `index + 1`, `repeat = count`, цвет берётся из регистра, регистр не меняется |
| Пропуск | `index += count` (встаёт на последний пропущенный), `repeat = 0`, ничего не рисуется, регистр не меняется |

Следствия:
- Повтор после пропуска повторяет последний **реальный** цвет.
- Повтор до первого реального пикселя кадра законен и рисует `{0,0,0,0}` — прозрачный чёрный. Генерировать так смысла нет.
- Дельта-команды (форматы 7/8) прибавляются к регистру. В начале кадра регистр равен нулю, поэтому дельта первой команды отсчитывается от нуля.

Ограничения (нарушение даёт `ERROR_IDX_OVERFLOW`, кадр не засчитывается):
- `index + repeat <= size_x * size_y` для каждой рисуемой серии;
- пропуск может выходить за край кадра только если после него нет рисующих команд.

Пиксели, не затронутые ни одной командой, остаются чёрными.

Порядок команд не обязан быть возрастающим для форматов с явным индексом (0, 1 и несжатые команды 7/8). Для команд без индекса порядок задаётся самим потоком.

## 6. Форматы команд

Нотация битов: старший бит слева, байты по порядку в файле.

### 6.1. Формат 0 — RGB

```
IIIIIIII IIIIIIII RRRRRRRR GGGGGGGG BBBBBBBB      (5 байт)
```
`index` — big-endian, 0..`size_x*size_y-1`. Альфа = 255.

### 6.2. Формат 1 — RGBA

```
IIIIIIII IIIIIIII RRRRRRRR GGGGGGGG BBBBBBBB AAAAAAAA   (6 байт)
```

### 6.3. Формат 7 — RGB, разностное сжатие

Тип определяется старшим битом первого байта (`F`).

**F = 0, несжатый пиксель (5 байт):**
```
0IIIIIII IIIIIIII RRRRRRRR GGGGGGGG BBBBBBBB
```
Индекс 15-битный, поэтому меньше 32768. Цвет записывается в регистр, альфа = 255.

**F = 1, дельта (2 байта):**
```
1RRRRRGG GGGBBBBB
```
`index + 1`. Каждое поле — 5 бит (0..31); дельта = поле − 15, то есть −15..+16. Дельта прибавляется к регистру по модулю 256, альфа не меняется.

### 6.4. Формат 8 — RGBA, разностное сжатие

**F = 0, несжатый пиксель (6 байт):**
```
0IIIIIII IIIIIIII RRRRRRRR GGGGGGGG BBBBBBBB AAAAAAAA
```

**F = 1, дельта (2 байта):**
```
1RRRRGGG GBBBBAAA
```
`index + 1`. R, G, B — 4 бита, дельта = поле − 7 (−7..+8). A — 3 бита, дельта = поле − 3 (−3..+4). Сложение по модулю 256.

### 6.5. Формат 14 — RGB555 с повтором и пропуском

Индексов нет, все команды идут подряд от пикселя 0.

**Пиксель (2 байта), первый бит 0:**
```
0RRRRRGG GGGBBBBB
```
`index + 1`. Компоненты 5-битные, расширяются до 8 бит как `(v << 3) | (v >> 2)` (0→0x00, 31→0xFF). Альфа = 255. Цвет записывается в регистр.

**Повтор (1 байт):**
```
11NNNNNN
```
`count = N + 1` (1..64) **новых** пикселей цвета из регистра, начиная с `index + 1`. После команды `index` указывает на последний из них.

**Пропуск (1 байт):**
```
10NNNNNN
```
`count = N + 1` (1..64) пикселей не рисуются. `index += count`. Регистр не меняется.

Пример (строка 8×1):

| Команда | Байты | Результат |
|---|---|---|
| пиксель красный | `7C 00` | 0 = красный |
| повтор 2 | `C1` | 1, 2 = красный |
| пропуск 2 | `81` | 3, 4 пусто |
| повтор 1 | `C0` | 5 = красный |
| пиксель зелёный | `03 E0` | 6 = зелёный |

`frame_ops = 5`, итог: `R R R . . R G .`

## 7. Воспроизведение

Пусть `F = img_frames`, `P = img_plays`. Каждый раз, когда приходит время сменить кадр (истёк `frame_timeout` текущего кадра или включён режим игнорирования таймаутов), выполняется:

```
если текущий кадр < F            → следующий кадр
иначе если P == 0                 → кадр 1 (бесконечно)
иначе если завершено < P - 1      → кадр 1, завершено += 1
иначе                             → остаться на последнем кадре
```

| `img_frames` | `img_plays` | Поведение |
|---|---|---|
| 1 | любое | Статичная картинка |
| > 1 | 0 | Анимация по кругу бесконечно |
| > 1 | N | Анимация проигрывается N раз, затем стоит на последнем кадре |

Время показа кадра — `frame_timeout` этого кадра. Если в эффекте включён `SetIgnoreFrameTimeout(true)`, кадр меняется при каждом вызове, а скорость определяется частотой кадров `FrameManager`.

Если кадр не удалось разобрать (ошибка чтения, обрезанные данные, переполнение индекса), позиция воспроизведения не сдвигается: при следующем вызове этот же кадр разбирается заново. После 5 ошибок подряд файл закрывается; при `SetAutoReopen(true)` он переоткрывается и воспроизведение начинается сначала.

## 8. Альфа-канал

Парсер передаёт все четыре компоненты как есть и пиксели по альфе не отбрасывает. Что делать с альфой, решает потребитель. Текущий `FrameEffectReader` альфу не учитывает и рисует RGB любого пикселя. Прозрачные пиксели нужно выражать пропуском (формат 14) или не включать в кадр вовсе (форматы с индексом).

## 9. Отличия от версии 2

Двоичная структура не изменилась. Отличия:

| | Версия 2 | Версия 3 |
|---|---|---|
| Байт 9 | `img_repeats`: 0 и 1 — один раз, 255 — бесконечно, 2..254 — N раз | `img_plays`: 0 — бесконечно, N — N раз |
| Поле кадра | `frame_pixels` | `frame_ops` (то же значение, новое имя) |
| Повтор (формат 14) | не работал: серия затиралась следующим пикселем | работает по разделу 6.5 |
| Пропуск (формат 14) | обнулял регистр цвета, выдавал фиктивный пиксель с A = 0 | регистр не трогает, ничего не выдаёт |
| Пиксели с A < 255 | отбрасывались эффектом | передаются, эффект пока рисует их как непрозрачные |

Файлы версии 2 открываются: `img_repeats` пересчитывается в `img_plays` по таблице выше.

## 10. Ошибки парсера

| Код | Имя | Тип | Причина |
|---|---|---|---|
| 0 | `ERROR_OK` | — | — |
| −1 | `ERROR_INVALID_FILE` | фатальная | нет сигнатуры `PXL` |
| −2 | `ERROR_VERSION` | фатальная | неподдерживаемая версия |
| −3 | `ERROR_SIZE` | фатальная | размер не совпадает с экраном |
| −4 | `ERROR_FORMAT` | фатальная | неподдерживаемый `format_strip`/`format_color` |
| −5 | `ERROR_NOFRAMES` | фатальная | `img_frames == 0` |
| −6 | `ERROR_OPEN_FILE` | восстановимая | не открылся источник или не прочитался заголовок |
| 1 | `ERROR_READ1_ZERO` | восстановимая | не прочитался заголовок кадра |
| 2 | `ERROR_READ2_ZERO` | восстановимая | ридер не вернул данные при дочитке команд |
| 3 | `ERROR_IDX_OVERFLOW` | восстановимая | серия выходит за пределы кадра |
| 4 | `ERROR_DATA_TRUNCATED` | восстановимая | команда длиннее прочитанных данных: файл обрезан или ридер вернул неполную команду |

Фатальные (отрицательные, кроме −6) блокируют разбор до переоткрытия файла. Положительные сбрасываются при следующем успешном кадре.

## 11. Требования к источнику данных

- Буфер ридера должен вмещать не меньше 10 байт (заголовок файла читается одним запросом).
- Ридер может вернуть меньше запрошенного; парсер дочитывает данные, когда в буфере остаётся меньше максимальной длины команды.

## 12. Планы на будущее (не входит в версию 3)

- Поле длины кадра в байтах (`uint32_t`, так как кадр 255×255 RGBA без сжатия весит около 390 КБ) в заголовке кадра. Оно даст точный размер чтения, проверку целостности кадра и возможность пропустить битый кадр без переоткрытия файла.
- Команда серии со встроенным цветом (например, `1NNNNNNN RRRRRRRR GGGGGGGG BBBBBBBB` для RGB888), не зависящий от регистра цвета.
- Раскладки ленты кроме `STRIP_LINE`.
