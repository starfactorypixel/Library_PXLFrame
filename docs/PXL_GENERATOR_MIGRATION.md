# Генератор PXL: переход на версию 3

Полное описание формата — `PXL_FORMAT.md`.

## Обязательно

1. **Байт 3 (`version`)** — писать `3`.
2. **Байт 9 (`img_plays`)** — новый смысл:
   | Нужно | Было (v2) | Писать (v3) |
   |---|---|---|
   | бесконечно | 255 | **0** |
   | один раз | 0 или 1 | **1** |
   | N раз | N | N |
   | статичная картинка | 0 | `img_frames = 1`, `img_plays = 1` |
3. **Байты 2–3 заголовка кадра (`frame_ops`)** — число **команд** кадра, включая повторы и пропуски. Двоичная запись не изменилась, изменилось только имя поля.
4. **Серии не выходят за кадр**: для каждого пикселя и повтора `index + длина <= size_x * size_y`. Иначе кадр отбрасывается.
5. **Каждый кадр — полное изображение.** Буфер перед кадром очищается, кадр не может ссылаться на предыдущий.
6. **Прозрачные пиксели не выдавать как пиксели.** Эффект больше не отбрасывает пиксели с A < 255 и нарисует их RGB. Используйте пропуск (формат 14) или просто не записывайте такие пиксели (форматы 0, 1, 7, 8).

## Формат 14 (RGB555): повтор и пропуск теперь работают

- `11NNNNNN` — повтор: ещё `N+1` пикселей (1..64) цвета **последнего реального пикселя**, сразу после него.
- `10NNNNNN` — пропуск `N+1` пикселей (1..64). Цвет для следующего повтора **не сбрасывается**.
- Разрешено: `пиксель → пропуск → повтор` (повтор возьмёт цвет пикселя до пропуска).
- Не генерировать повтор до первого реального пикселя кадра: он нарисует чёрный.
- Серии длиннее 64 разбивать на несколько команд повтора подряд.

Проверочный пример, строка 8×1, `frame_ops = 5`:
```
7C 00   C1   81   C0   03 E0
→ R R R . . R G .
```

## Форматы 7 и 8 (дельты)

- Регистр цвета в начале каждого кадра равен `{0,0,0,0}`. Первую команду кадра делать **несжатой** (с индексом и полным цветом).
- Несжатая команда: индекс < 32768 (старший бит занят флагом).

## Без изменений

- Заголовки (`uint16_t`) — little-endian. Индекс в командах — big-endian.
- Структура заголовка файла, заголовка кадра и всех команд.

## Проверка

- Старые файлы v2 продолжают открываться (байт 9 пересчитывается), но новые файлы генерировать только как v3.
- После генерации прогнать файл через парсер: все кадры должны разбираться с `ERROR_OK`, число проигрываний должно совпадать с ожидаемым.
